# V1 design

## Purpose

V1 adds current news, NFL schedules, player statistics, projections, and deeper matchup simulations. V1 keeps Sleeper as the league system of record.

## V0 boundary

The documented Sleeper API supplies league, roster, matchup, transaction, player-profile, draft, and trending data. It does not supply an NFL schedule or a player-stat feed.

The V0 rating uses prior fantasy scores from the selected league. The rating does not use NFL opponents, weather, betting lines, or external projections.

## Recommended sources

| Source | Data | Cost and access | V1 use |
| --- | --- | --- | --- |
| [Sleeper API](https://docs.sleeper.com/) | League settings, rosters, matchups, transactions, player profiles, and trends | Public read-only API for non-commercial use | Keep as the league system of record |
| [Gemini Google Search grounding](https://ai.google.dev/gemini-api/docs/google-search) | Current web news with source links | Gemini usage charges and grounding limits apply | Find recent player and team news |
| [nflverse](https://github.com/nflverse) | Historical play-by-play, weekly player statistics, rosters, and schedules | Open data with source-specific licenses | Build features and run backtests |
| [SportsDataIO NFL](https://sportsdata.io/developers/workflow-guide/nfl) | Schedules, injuries, depth charts, projections, fantasy points, and licensed news | Commercial license | Provide one integrated production feed |
| [Sportradar NFL](https://developer.sportradar.com/football/docs/nfl-ig-api-basics) | Schedules, statistics, play-by-play, standings, and change feeds | Commercial B2B access | Provide a high-reliability production feed |
| [National Weather Service API](https://www.weather.gov/documentation/services-web-api) | Forecasts and alerts for United States game locations | Public API | Add outdoor game weather features |

Start with Gemini grounding and nflverse. This choice limits initial cost and supports a useful prototype.

Select SportsDataIO when one licensed feed must supply projections, injuries, schedules, and news. Compare its contract with Sportradar before production use.

## Data model

Use stable internal identifiers. Store each external identifier in a separate mapping table.

1. `players` stores the internal player record.
2. `player_external_ids` maps Sleeper, nflverse, and vendor identifiers.
3. `games` stores the NFL schedule and game status.
4. `player_game_stats` stores observed player results.
5. `player_status_events` stores injuries, practice status, and depth-chart changes.
6. `news_items` stores a URL, publisher, publication time, retrieval time, and player links.
7. `projections` stores a model version, feature timestamp, mean, and uncertainty range.
8. `fantasy_league_snapshots` stores Sleeper settings and roster state.

Every current record needs a source timestamp and a retrieval timestamp. These timestamps let the agent state the age of each fact.

## Ingestion plan

1. Poll Sleeper league data after each waiver period and lineup deadline.
2. Load nflverse schedules and statistics after its published updates.
3. Search current news when a user asks, or on a short scheduled interval.
4. Poll injury and depth-chart feeds more often near kickoff.
5. Refresh weather forecasts for outdoor games during the final 48 hours.
6. Normalize identifiers before the feature calculation starts.

Respect each provider's rate limit, attribution rule, cache rule, and license. Do not redistribute a licensed feed without contract permission.

## News workflow

Gemini Google Search grounding can provide recent results and citations. The workflow must preserve the source links from the grounding response.

1. Search with a player name, NFL team, and a limited time range.
2. Reject an item that lacks a publication time or a source URL.
3. Merge duplicate reports that refer to the same event.
4. Prefer a team statement, league report, or direct reporter source.
5. Mark a report as confirmed, attributed, or unverified.
6. Show the publication time and source beside each claim.

Do not let one unverified report change a projection without a clear warning.

## Player projection

The first projection model can use a transparent statistical baseline. A complex model needs evidence from backtests before adoption.

1. Convert the Sleeper scoring settings into point weights.
2. Calculate recent opportunities, such as snaps, routes, targets, carries, and red-zone work.
3. Weight recent games more than older games.
4. Adjust for the expected team pace and game script.
5. Adjust for the opposing defense by position and play type.
6. Adjust for injuries, practice status, depth-chart changes, weather, and rest.
7. Return the expected points and an uncertainty interval.

Report a median, a floor, and a ceiling. Do not report one precise number without an uncertainty statement.

## Fantasy roster matchup simulation

The simulation uses each starter's outcome distribution. It must use the selected league's scoring settings.

1. Generate a distribution for each starting player.
2. Include correlations between players in the same NFL game.
3. Simulate both fantasy rosters at least 10,000 times.
4. Report the win probability, median score, and score interval.
5. Explain the positions that create the largest advantage.
6. Show the news or injury event that changes the result most.

The result remains a forecast. It does not guarantee a winner.

## Agent tools

V1 can add these read-only tools:

- `searchPlayerNews` returns cited and time-bounded reports.
- `getNflSchedule` returns opponents, kickoff times, venues, and game status.
- `getPlayerGameLog` returns normalized weekly statistics.
- `getInjuryReport` returns status changes and source times.
- `getWeatherForecast` returns game-time weather and forecast age.
- `projectPlayer` returns scoring-aware expected points and uncertainty.
- `simulateMatchup` returns roster win probabilities and key drivers.
- `explainProjectionChange` compares two projection versions.

## Quality checks

Build a historical evaluation set before the model affects lineup advice.

- Measure mean absolute error for projected fantasy points.
- Measure root mean square error to expose large misses.
- Measure interval coverage for the floor and ceiling.
- Measure Brier score and calibration for win probabilities.
- Compare the model with a season-average baseline.
- Split tests by season to prevent future data from entering past features.
- Track results by position, injury status, and forecast horizon.

Later Judgment integration can store these cases and score agent answers. The evaluation must verify citations, freshness, arithmetic, and uncertainty language.

## Delivery stages

### V1.1

Add Google Search grounding for cited news. Add nflverse schedules and weekly statistics. Add identifier mapping and data timestamps.

### V1.2

Add the baseline player projection. Add historical backtests and calibration reports.

### V1.3

Add roster simulations, injury updates, and weather. Add an explanation for every important projection change.

### Production review

Compare the licensed feeds. Review provider terms, expected request volume, latency, attribution, data retention, and redistribution rights.
